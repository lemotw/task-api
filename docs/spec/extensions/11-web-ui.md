# 11. 擴展:前端

規範用語見 [00-overview](../00-overview.md#1-規範用語)。本擴展依賴 [01-domain](../core/01-domain.md) 和 [02-api](../core/02-api.md)。

## 1. 定位

前端有兩個頁面:

| 路徑 | 頁面 | 使用者 |
|---|---|---|
| `/` | 任務管理頁面 | 一般使用者,做日常的新增、完成、修改、刪除 |
| `/test` | 測試主控台 | 開發者和評審,手動測試 API,包含不合法的輸入 |

## 2. 提供方式

- **UI-1**:前端 MUST 用 `go:embed` 打包進伺服器 binary。`GET /` MUST 提供任務管理頁面,`GET /test` MUST 提供測試主控台,兩者都回應 `200` 和 `Content-Type: text/html; charset=utf-8`。
- **UI-2**:對 `/` 或 `/test` 使用其他方法時,伺服器 MUST 回傳 `405`,`Allow` MUST 為 `GET`,回應格式 MUST 符合 `API-16`。
- **UI-3**:前端 MUST NOT 需要額外的建置步驟或獨立的伺服器。
- **UI-4**:前端 MUST NOT 載入外部資源(CDN、外部字型等),在無網路環境下 MUST 可正常運作。
- **UI-5**:每個頁面 SHOULD 是單一 HTML 檔,CSS 和 JavaScript 內嵌其中。
- **UI-20**:兩個頁面 SHOULD 互相連結。

## 3. API 使用

- **UI-6**:前端 MUST 只呼叫 `02-api` 定義的公開端點。系統 MUST NOT 為前端新增專用端點。
- **UI-7**:前端佔用的路徑 MUST 只有 `/` 和 `/test`,且 MUST NOT 改變 `/tasks` 和 `/tasks/{id}` 的行為。其他路徑 MUST 仍依 `API-15` 回傳 `404`。

## 4. 任務管理頁面(`/`)

- **UI-21**:頁面 MUST 顯示任務列表,且 MUST 能新增任務、切換完成狀態、修改名稱、刪除任務。
- **UI-22**:操作成功後,頁面 MUST 重新取得並顯示列表。
- **UI-23**:操作失敗時,頁面 MUST 顯示伺服器回傳的 `error` 訊息;網路失敗時 MUST 顯示錯誤,MUST NOT 無聲失敗。
- **UI-24**:沒有任務時,頁面 SHOULD 顯示空狀態提示。

## 5. 測試主控台(`/test`)

- **UI-8**:主控台 MUST 顯示任務列表,且 MUST 能新增、編輯、刪除任務。
- **UI-9**:新增、編輯、刪除成功後,主控台 MUST 重新取得並顯示列表。
- **UI-10**:沒有任務時,主控台 SHOULD 顯示空狀態提示。

### 請求檢視

- **UI-11**:每次請求後,主控台 MUST 顯示請求方法、路徑、請求 body、回應狀態碼和原始回應內容。`204` MUST 明確標示為沒有回應內容。
- **UI-12**:網路失敗時,主控台 MUST 顯示錯誤,MUST NOT 無聲失敗。
- **UI-13**:主控台 SHOULD 保留本次頁面工作階段的請求紀錄,最新的在最上方。

### 測試錯誤路徑

- **UI-14**:主控台 MUST 提供可自由編輯的 JSON 輸入,並 MUST 能指定目標 `id`,讓使用者送出不合法的內容,例如 `"status": 2`、缺少欄位或語法錯誤的 JSON。
- **UI-15**:主控台 MUST NOT 在送出前驗證或修正輸入;驗證結果 MUST 來自伺服器。

## 6. 呈現與安全

- **UI-16**:兩個頁面 MUST 以純文字方式呈現 `name` 和回應內容(例如 `textContent`),MUST NOT 將其當作 HTML 解析。
- **UI-25**:兩個頁面顯示 `name` 時 MUST 保留連續空白和換行,與 `DOM-6` 儲存的內容一致。
- **UI-17**:由於 API 沒有驗證機制,此服務 SHOULD NOT 暴露於公開網路。

## 7. 測試

- **UI-18**:自動化測試 MUST 涵蓋 `UI-1`、`UI-2`,並確認 `/tasks` 行為不受影響。
- **UI-19**:驗收時 MUST 在瀏覽器中實際操作 `UI-8`、`UI-11`、`UI-14`、`UI-16`、`UI-21`、`UI-23`、`UI-25`。

## 決策與理由

| 決策 | 理由 |
|---|---|
| 分成管理頁面和測試主控台 | 管理頁面給一般使用;主控台不驗證輸入,才測得到錯誤路徑 |
| 管理頁面放在 `/` | 一般使用者打開網址就看到 |
| `go:embed` 同源提供 | 不需要 CORS、不多一個容器,`docker run` 就能使用 |
| 不使用前端框架 | 頁面簡單,引入框架就需要建置流程 |
