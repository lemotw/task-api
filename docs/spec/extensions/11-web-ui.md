# 11. 擴展:測試用前端

規範用語見 [00-overview](../00-overview.md#1-規範用語)。本擴展依賴 [02-api](../core/02-api.md)。

## 1. 定位

這是給開發者和評審手動測試 API 的主控台,不是給一般使用者的產品介面。

## 2. 提供方式

- **UI-1**:前端 MUST 用 `go:embed` 打包進伺服器 binary,並由 `GET /` 提供,回應 `200` 和 `Content-Type: text/html; charset=utf-8`。
- **UI-2**:對 `/` 使用其他方法時,伺服器 MUST 回傳 `405`,`Allow` MUST 為 `GET`,回應格式 MUST 符合 `API-16`。
- **UI-3**:前端 MUST NOT 需要額外的建置步驟或獨立的伺服器。
- **UI-4**:前端 MUST NOT 載入外部資源(CDN、外部字型等),在無網路環境下 MUST 可正常運作。
- **UI-5**:前端 SHOULD 是單一 HTML 檔,CSS 和 JavaScript 內嵌其中。

## 3. API 使用

- **UI-6**:前端 MUST 只呼叫 `02-api` 定義的公開端點。系統 MUST NOT 為前端新增專用端點。
- **UI-7**:新增前端 MUST NOT 改變 `02-api` 定義的任何行為。

## 4. 功能

- **UI-8**:前端 MUST 顯示任務列表,且 MUST 能新增、編輯、刪除任務。
- **UI-9**:新增、編輯、刪除成功後,前端 MUST 重新取得並顯示列表。
- **UI-10**:沒有任務時,前端 SHOULD 顯示空狀態提示。

### 請求檢視

- **UI-11**:每次請求後,前端 MUST 顯示請求方法、路徑、請求 body、回應狀態碼和原始回應內容。`204` MUST 明確標示為沒有回應內容。
- **UI-12**:網路失敗時,前端 MUST 顯示錯誤,MUST NOT 無聲失敗。
- **UI-13**:前端 SHOULD 保留本次頁面工作階段的請求紀錄,最新的在最上方。

### 測試錯誤路徑

- **UI-14**:前端 MUST 提供可自由編輯的 JSON 輸入,並 MUST 能指定目標 `id`,讓使用者送出不合法的內容,例如 `"status": 2`、缺少欄位或語法錯誤的 JSON。
- **UI-15**:前端 MUST NOT 在送出前驗證或修正輸入;驗證結果 MUST 來自伺服器。

## 5. 安全

- **UI-16**:前端 MUST 以純文字方式呈現 `name` 和回應內容(例如 `textContent`),MUST NOT 將其當作 HTML 解析。
- **UI-17**:由於 API 沒有驗證機制,此服務 SHOULD NOT 暴露於公開網路。

## 6. 測試

- **UI-18**:自動化測試 MUST 涵蓋 `UI-1`、`UI-2`,並確認 `/tasks` 行為不受影響。
- **UI-19**:驗收時 MUST 在瀏覽器中實際操作 `UI-8`、`UI-11`、`UI-14`、`UI-16`。

## 決策與理由

| 決策 | 理由 |
|---|---|
| 測試主控台,不做一般使用者介面 | 使用者介面的表單會先擋掉不合法輸入,反而測不到錯誤路徑 |
| `go:embed` 同源提供 | 不需要 CORS、不多一個容器,`docker run` 就能使用 |
| 不使用前端框架 | 頁面簡單,引入框架就需要建置流程 |
