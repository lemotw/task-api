# `internal/webui` 測試提案

臨時 review 文件,不會留存,也不具規範效力。需求定義以 `docs/spec` 為準。

- **測試替身:** 不需要
- **執行:** `go test -race ./internal/webui`
- **RED 階段:** 空殼會 `panic` 並中止整個測試程式,所以要用 `-run` 逐一執行,確認每個測試都失敗。

**測試方式:** 自動測試只驗證 HTTP 行為和內容規則。互動行為在瀏覽器手動驗收。

## 成功

| 情境 | 預期 | 需求 |
|---|---|---|
| `GET /` | `200`、`text/html; charset=utf-8` | `UI-1` |
| 檢查 HTML 內容 | 沒有外部資源網址 | `UI-4` |

## 失敗

| 情境 | 預期 | 需求 |
|---|---|---|
| `POST /` | `405`、`Allow: GET`、JSON 錯誤格式 | `UI-2` |

## 瀏覽器驗收(`UI-19`)

| 操作 | 預期 | 需求 |
|---|---|---|
| 新增、編輯、刪除 | 列表自動更新 | `UI-8`、`UI-9` |
| 任一請求 | 顯示方法、路徑、body、狀態碼和原始回應 | `UI-11` |
| 刪除成功 | 明確標示沒有回應內容 | `UI-11` |
| 送出 `{"name":"a","status":2}` 和語法錯誤的 JSON | 前端不阻擋,顯示伺服器的 `400` | `UI-14`、`UI-15` |
| 建立名為 `<img src=x onerror=alert(1)>` 的任務 | 顯示為純文字,不執行 | `UI-16` |
| 回應內容含 HTML | 顯示為純文字,不執行 | `UI-16` |
| 指定不存在或不合法的 `id` | 顯示伺服器的原始 JSON,前端不修改 | `UI-11`、`UI-14` |
| 操作時檢查網路請求 | 沒有對外部網站的請求 | `UI-4` |
| 關閉伺服器後送出請求 | 顯示網路錯誤 | `UI-12` |

## 已定案

| 問題 | 決定 |
|---|---|
| 前端佔用 `/` 與 API 規則的衝突 | `API-19` 限定範圍,前端只佔用 `/`(`UI-7`) |
## 放在其他 package 的測試

`httpapi` 負責驗證「掛載 UI 後 API 行為不變」和「未知路徑仍回 `404`」(`UI-7`),因為這些行為由路由決定。

## 不納入

- **從其他目錄執行 binary:** `go:embed` 已保證不依賴原始 HTML 檔。
- **自動化的網路封鎖測試:** 以靜態檢查 HTML,加上瀏覽器驗收時檢查網路請求取代。
